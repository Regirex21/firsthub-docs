## ¿Qué es un Differential Drivetrain?

Un Differential Drivetrain utiliza lados izquierdo y derecho independientes para mover el robot.

La mayoría de robots FRC tipo tanque utilizan:

- 2 motores izquierdos
- 2 motores derechos
- Leaders y followers
- Control arcade con control Xbox
- Motores brushless conectados por CAN

:::note[Importante]
Un drivetrain diferencial puede utilizar distintos estilos de control.

En esta guía utilizaremos Arcade Drive:
- Stick izquierdo = adelante y atrás
- Stick derecho = giro
:::

## CAN IDs


:::caution[CAN IDs reservados]
En un robot FRC normalmente algunos CAN IDs ya están ocupados por dispositivos del sistema de control.

Comúnmente:

- CAN ID 0 = roboRIO
- CAN ID 1 = PDH o PDP

Por eso normalmente se recomienda comenzar motores desde IDs más altos como:

- 10
- 11
- 12
- 13

Esto ayuda a evitar conflictos y hace más fácil identificar dispositivos.
:::
Cada controlador de motor necesita un CAN ID único.

En este ejemplo utilizaremos:

| Motor | CAN ID |
|---|---|
| Left Leader | 10 |
| Left Follower | 11 |
| Right Leader | 12 |
| Right Follower | 13 |

:::caution[Importante]
Nunca utilices dos dispositivos con el mismo CAN ID.
:::

## Importando librerías

Primero agregaremos las librerías necesarias.

```java
package frc.robot;

import com.revrobotics.spark.SparkLowLevel.MotorType;
import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkBase.PersistMode;
import com.revrobotics.spark.SparkBase.ResetMode;
import com.revrobotics.spark.config.SparkMaxConfig;

import edu.wpi.first.wpilibj.TimedRobot;
import edu.wpi.first.wpilibj.XboxController;
import edu.wpi.first.wpilibj.drive.DifferentialDrive;
```

:::tip[¿Qué hacen estas librerías?]
Estas librerías permiten controlar motores, leer controles Xbox y utilizar herramientas de drivetrain incluidas en WPILib.
Recuerda tener siempre las librerías actualizadas para evitar problemas de compatibilidad.
:::

:::caution[REVLib cambia esta API cada temporada]
Desde REVLib 2025, `SparkMax` ya no se configura llamando métodos como `.setInverted()` o `.follow()` directamente sobre el motor — eso quedó obsoleto. Ahora se arma un objeto `SparkMaxConfig`, se le indican los ajustes deseados, y se aplica al motor con `.configure(config, ResetMode, PersistMode)`. Muchos ejemplos que circulan en internet (incluida documentación desactualizada de WPILib) todavía muestran el patrón antiguo, que no compila contra versiones recientes de REVLib. Verifica siempre contra la [documentación oficial de REVLib](https://docs.revrobotics.com/revlib/spark/configuring-a-spark) antes de copiar código de otra fuente.
:::

## ¿Qué son Leaders y Followers?

En un drivetrain FRC moderno normalmente existen:

- Motores leaders
- Motores followers

El motor leader recibe comandos directamente desde el código.

El follower copia automáticamente el comportamiento del leader del mismo lado.

Esto permite:

- Simplificar el código
- Mantener sincronizados los motores
- Reducir errores

## Configurando Followers

Dentro de `robotInit()` configuraremos followers usando `SparkMaxConfig`.

```java
@Override
public void robotInit() {

    SparkMaxConfig leftFollowerConfig = new SparkMaxConfig();
    leftFollowerConfig.follow(leftLeader);
    leftFollower.configure(leftFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

    SparkMaxConfig rightFollowerConfig = new SparkMaxConfig();
    rightFollowerConfig.follow(rightLeader);
    rightFollower.configure(rightFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

}
```

:::note[¿Qué hace `.configure()`?]
`ResetMode.kResetSafeParameters` restablece los parámetros del controlador a sus valores por defecto antes de aplicar la nueva configuración, y `PersistMode.kPersistParameters` guarda esos ajustes en la memoria no volátil del SparkMax para que sobrevivan un ciclo de energía.
:::

## Invirtiendo motores

En la mayoría de drivetrains un lado debe invertirse.

```java
@Override
public void robotInit() {

    SparkMaxConfig leftFollowerConfig = new SparkMaxConfig();
    leftFollowerConfig.follow(leftLeader);
    leftFollower.configure(leftFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

    SparkMaxConfig rightFollowerConfig = new SparkMaxConfig();
    rightFollowerConfig.follow(rightLeader);
    rightFollower.configure(rightFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

    SparkMaxConfig rightLeaderConfig = new SparkMaxConfig();
    rightLeaderConfig.inverted(true);
    rightLeader.configure(rightLeaderConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

}
```

:::note[¿Por qué invertir un lado?]
Los motores de ambos lados están montados en direcciones opuestas.
Sin inversión, un lado avanzará mientras el otro retrocede.
Eso puede dañar las cajas de engranes.
:::

## ¿Cómo funciona Arcade Drive?

Con este sistema:

- Stick izquierdo → adelante y atrás
- Stick derecho → giro o pivote

Si avanzas y giras al mismo tiempo:
- el robot girará suavemente mientras avanza

Este es uno de los métodos de control más utilizados en FRC.

## Código completo del robot

```java
package frc.robot;

import com.revrobotics.spark.SparkLowLevel.MotorType;
import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkBase.PersistMode;
import com.revrobotics.spark.SparkBase.ResetMode;
import com.revrobotics.spark.config.SparkMaxConfig;

import edu.wpi.first.wpilibj.TimedRobot;
import edu.wpi.first.wpilibj.XboxController;
import edu.wpi.first.wpilibj.drive.DifferentialDrive;

public class Robot extends TimedRobot {

    // Left side motors
    private final SparkMax leftLeader =
        new SparkMax(10, MotorType.kBrushless);

    private final SparkMax leftFollower =
        new SparkMax(11, MotorType.kBrushless);

    // Right side motors
    private final SparkMax rightLeader =
        new SparkMax(12, MotorType.kBrushless);

    private final SparkMax rightFollower =
        new SparkMax(13, MotorType.kBrushless);

    // Xbox controller
    private final XboxController controller =
        new XboxController(0);

    // Differential drivetrain
    private final DifferentialDrive drive =
        new DifferentialDrive(leftLeader, rightLeader);

    @Override
    public void robotInit() {

        // Configure followers
        SparkMaxConfig leftFollowerConfig = new SparkMaxConfig();
        leftFollowerConfig.follow(leftLeader);
        leftFollower.configure(leftFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

        SparkMaxConfig rightFollowerConfig = new SparkMaxConfig();
        rightFollowerConfig.follow(rightLeader);
        rightFollower.configure(rightFollowerConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);

        // Invert right side
        SparkMaxConfig rightLeaderConfig = new SparkMaxConfig();
        rightLeaderConfig.inverted(true);
        rightLeader.configure(rightLeaderConfig, ResetMode.kResetSafeParameters, PersistMode.kPersistParameters);
    }

    @Override
    public void teleopPeriodic() {

        // Forward and backward
        double speed =
            -controller.getLeftY();

        // Rotation
        double rotation =
            controller.getRightX();

        // Drive robot
        drive.arcadeDrive(speed, rotation);
    }
}

```
## Métodos importantes

<Tabs>
  <TabItem label="robotInit">
    <p>
      Este método se ejecuta una sola vez cuando el programa del robot inicia.
      Se utiliza para preparar el robot antes de comenzar a operar, inicializando
      motores, sensores, controles y cualquier configuración necesaria para el resto del código.
    </p>
  </TabItem>

  <TabItem label="teleopPeriodic">
    <p>
      Este método se ejecuta continuamente mientras el robot está en modo Teleoperated.
      Aquí normalmente se procesa la entrada de joysticks y controles para permitir
      que el driver maneje el robot manualmente durante el partido.
    </p>
  </TabItem>

  <TabItem label="autonomousPeriodic">
    <p>
      Este método se ejecuta repetidamente durante el modo Autonomous.
      Se utiliza para programar movimientos y acciones automáticas
      que el robot realiza sin intervención del conductor.
    </p>
  </TabItem>

  <TabItem label="disabledInit">
    <p>
      Este método se ejecuta cuando el robot entra en estado deshabilitado.
      Generalmente se utiliza para detener sistemas, reiniciar variables
      o asegurar que el robot permanezca en un estado seguro.
    </p>
  </TabItem>
