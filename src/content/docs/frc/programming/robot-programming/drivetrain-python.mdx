## ¿Qué es un Differential Drivetrain?

Un Differential Drivetrain utiliza lados izquierdo y derecho independientes para mover el robot, igual que en la versión Java de esta guía.

La mayoría de robots FRC tipo tanque utilizan:

- 2 motores izquierdos
- 2 motores derechos
- Leaders y followers
- Control arcade con control Xbox
- Motores brushless conectados por CAN

<Aside type="note" title="Importante">
En esta guía utilizaremos Arcade Drive:
- Stick izquierdo = adelante y atrás
- Stick derecho = giro
</Aside>

## Estructura del proyecto

RobotPy genera dos archivos principales en la carpeta del proyecto:

<FileTree>
- robot.py
- pyproject.toml
</FileTree>

`robot.py` contiene la clase principal del robot. `pyproject.toml` define las dependencias del proyecto, incluyendo la versión de RobotPy y las librerías de fabricantes que agregues.

<Aside type="note" title="Agregar la librería de REV">

```bash

```
</Aside>

## CAN IDs

<Aside type="caution" title="CAN IDs reservados">
En un robot FRC normalmente algunos CAN IDs ya están ocupados por dispositivos del sistema de control.

Comúnmente:

- CAN ID 0 = roboRIO
- CAN ID 1 = PDH o PDP

Por eso normalmente se recomienda comenzar motores desde IDs más altos como 10, 11, 12 y 13.
</Aside>

Cada controlador de motor necesita un CAN ID único. En este ejemplo utilizaremos los mismos IDs que la versión Java:

| Motor | CAN ID |
|---|---|
| Left Leader | 10 |
| Left Follower | 11 |
| Right Leader | 12 |
| Right Follower | 13 |

## Importando librerías

```python
import wpilib
import rev

from wpilib.drive import DifferentialDrive
```

<Aside type="tip" title="¿Qué hacen estas librerías?">
`wpilib` provee las clases base del robot (TimedRobot, XboxController, DifferentialDrive). `rev` provee soporte para los motores SparkMax.
</Aside>

<Aside type="caution" title="REVLib cambia esta API cada temporada">
Desde REVLib 2025, la clase `rev.CANSparkMax` quedó obsoleta en favor de `rev.SparkMax`, y motores como `.setInverted()` o `.follow()` ya no se llaman directamente sobre el motor: se configuran armando un objeto `rev.SparkMaxConfig` y aplicándolo con `.configure(config, resetMode, persistMode)`. Muchos ejemplos que circulan en internet todavía usan el patrón antiguo, que no funciona con versiones recientes de RobotPy/REVLib. Verifica siempre contra la [documentación oficial de RobotPy REV](https://robotpy.readthedocs.io/projects/rev/en/stable/) antes de copiar código de otra fuente.
</Aside>

## Declarando la clase del robot

```python
class MyRobot(wpilib.TimedRobot):

    def robotInit(self):

        # Left side motors
        self.leftLeader = rev.SparkMax(
            10, rev.SparkLowLevel.MotorType.kBrushless)

        self.leftFollower = rev.SparkMax(
            11, rev.SparkLowLevel.MotorType.kBrushless)

        # Right side motors
        self.rightLeader = rev.SparkMax(
            12, rev.SparkLowLevel.MotorType.kBrushless)

        self.rightFollower = rev.SparkMax(
            13, rev.SparkLowLevel.MotorType.kBrushless)
```

---

## ¿Qué son Leaders y Followers?

En un drivetrain FRC moderno normalmente existen motores leaders y motores followers.

El motor leader recibe comandos directamente desde el código. El follower copia automáticamente el comportamiento del leader del mismo lado.

Esto permite:

- Simplificar el código
- Mantener sincronizados los motores
- Reducir errores

## Configurando Followers e inversión

Dentro de `robotInit()`, después de crear los motores, se configuran con objetos `SparkMaxConfig`:

```python
leftFollowerConfig = rev.SparkMaxConfig()
leftFollowerConfig.follow(self.leftLeader)
self.leftFollower.configure(
    leftFollowerConfig,
    rev.ResetMode.kResetSafeParameters,
    rev.PersistMode.kPersistParameters)

rightFollowerConfig = rev.SparkMaxConfig()
rightFollowerConfig.follow(self.rightLeader)
self.rightFollower.configure(
    rightFollowerConfig,
    rev.ResetMode.kResetSafeParameters,
    rev.PersistMode.kPersistParameters)

rightLeaderConfig = rev.SparkMaxConfig()
rightLeaderConfig.inverted(True)
self.rightLeader.configure(
    rightLeaderConfig,
    rev.ResetMode.kResetSafeParameters,
    rev.PersistMode.kPersistParameters)
```

<Aside type="note" title="¿Por qué invertir un lado?">
Los motores de ambos lados están montados en direcciones opuestas. Sin inversión, un lado avanzará mientras el otro retrocede, lo cual puede dañar las cajas de engranes.
</Aside>

## Configurando Arcade Drive

Ahora agregaremos control manual dentro de `teleopPeriodic()`.

```python
def teleopPeriodic(self):

    speed = -self.controller.getLeftY()
    rotation = self.controller.getRightX()

    self.drive.arcadeDrive(speed, rotation)
```

- `-self.controller.getLeftY()` lee el stick izquierdo para avanzar y retroceder.
- `self.controller.getRightX()` lee el stick derecho para girar.
- `self.drive.arcadeDrive(speed, rotation)` convierte ambos valores en movimiento para el drivetrain.

---

## ¿Cómo funciona Arcade Drive?

Con este sistema:

- Stick izquierdo → adelante y atrás
- Stick derecho → giro o pivote

Si avanzas y giras al mismo tiempo, el robot girará suavemente mientras avanza. Este es uno de los métodos de control más utilizados en FRC.

## Código completo del robot

```python
import wpilib
import rev

from wpilib.drive import DifferentialDrive


class MyRobot(wpilib.TimedRobot):

    def robotInit(self):

        # Left side motors
        self.leftLeader = rev.SparkMax(
            10, rev.SparkLowLevel.MotorType.kBrushless)

        self.leftFollower = rev.SparkMax(
            11, rev.SparkLowLevel.MotorType.kBrushless)

        # Right side motors
        self.rightLeader = rev.SparkMax(
            12, rev.SparkLowLevel.MotorType.kBrushless)

        self.rightFollower = rev.SparkMax(
            13, rev.SparkLowLevel.MotorType.kBrushless)

        # Followers
        leftFollowerConfig = rev.SparkMaxConfig()
        leftFollowerConfig.follow(self.leftLeader)
        self.leftFollower.configure(
            leftFollowerConfig,
            rev.ResetMode.kResetSafeParameters,
            rev.PersistMode.kPersistParameters)

        rightFollowerConfig = rev.SparkMaxConfig()
        rightFollowerConfig.follow(self.rightLeader)
        self.rightFollower.configure(
            rightFollowerConfig,
            rev.ResetMode.kResetSafeParameters,
            rev.PersistMode.kPersistParameters)

        # Invert right side
        rightLeaderConfig = rev.SparkMaxConfig()
        rightLeaderConfig.inverted(True)
        self.rightLeader.configure(
            rightLeaderConfig,
            rev.ResetMode.kResetSafeParameters,
            rev.PersistMode.kPersistParameters)

        # Xbox controller
        self.controller = wpilib.XboxController(0)

        # Differential drivetrain
        self.drive = DifferentialDrive(self.leftLeader, self.rightLeader)

    def teleopPeriodic(self):

        # Forward and backward
        speed = -self.controller.getLeftY()

        # Rotation
        rotation = self.controller.getRightX()

        # Drive robot
        self.drive.arcadeDrive(speed, rotation)
```

## Métodos importantes

<Tabs>
  <TabItem label="robotInit">
    <p>
      Se ejecuta una sola vez cuando el programa del robot inicia. Se utiliza para preparar
      el robot antes de comenzar a operar, inicializando motores, sensores, controles y
      cualquier configuración necesaria para el resto del código.
    </p>
  </TabItem>

  <TabItem label="teleopPeriodic">
    <p>
      Se ejecuta continuamente mientras el robot está en modo Teleoperated. Aquí normalmente
      se procesa la entrada de joysticks y controles para permitir que el driver maneje el
      robot manualmente durante el partido.
    </p>
  </TabItem>

  <TabItem label="autonomousPeriodic">
    <p>
      Se ejecuta repetidamente durante el modo Autonomous. Se utiliza para programar
      movimientos y acciones automáticas que el robot realiza sin intervención del conductor.
    </p>
  </TabItem>

  <TabItem label="disabledInit">
    <p>
      Se ejecuta cuando el robot entra en estado deshabilitado. Generalmente se utiliza para
      detener sistemas, reiniciar variables o asegurar que el robot permanezca en un estado
      seguro.
    </p>
  </TabItem>
</Tabs>
