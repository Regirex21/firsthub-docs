El área de programación desarrolla el software que controla el robot mediante **OpModes**: código que corre directamente en el Control Hub y se comanda de forma remota desde el Driver Hub.

En FTC, el código conecta hardware y estrategia: manejo, mecanismos, sensores, autónomos, visión y diagnóstico en pits.

<Aside type="note" title="Empieza aquí">
Si eres nuevo, comienza por Instalación y Herramientas. Puedes avanzar sin dominar programación al inicio, pero para crecer necesitarás practicar Blocks o Java.
</Aside>

## ¿Nuevo en programación?

Puedes empezar aunque no sepas programar. Muchos equipos comienzan con Blocks, el editor visual, y avanzan a Java cuando necesitan más control.

Apoyarse en miembros con más experiencia es clave, y no hay preguntas tontas.

<Aside type="tip" title="Recomendación">
Blocks es ideal para empezar rápido o para mentorías con estudiantes nuevos. Si tu equipo busca mayor profundidad técnica a largo plazo —o planea eventualmente pasar a FRC— Java es la mejor inversión.
</Aside>

## Ruta sugerida de aprendizaje

<Tabs>

<TabItem label="Nuevo">

<Steps>

1. Instalar herramientas  
2. Aprender la interfaz de Blocks o variables básicas en Java  
3. Entender qué es un OpMode  
4. Ejecutar un TeleOp de prueba  
5. Probar el drivetrain en el robot  

</Steps>

</TabItem>

<TabItem label="Intermedio">

<Steps>

1. OpModes lineales vs. iterativos  
2. Sensores y encoders  
3. Autónomo básico con temporizadores  
4. Introducción a visión (detección de props)  
5. Git colaborativo  

</Steps>

</TabItem>

<TabItem label="Avanzado">

<Steps>

1. Road Runner para trayectorias en autónomo  
2. FTC Dashboard para tuning en tiempo real  
3. Visión avanzada con TensorFlow  
4. Arquitectura por subsistemas  
5. PID control  

</Steps>

</TabItem>

</Tabs>

## Buenas prácticas

- Código entendible
- Cambios pequeños y probados
- Nombres claros
- Uso constante de Git
- Respaldos frecuentes
- Documentar decisiones
- Probar antes del evento

<Aside type="tip" title="Consejo">
Es mejor un OpMode simple y confiable que uno complejo e inestable.
</Aside>
