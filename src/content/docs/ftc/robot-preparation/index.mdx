Esta etapa consiste en preparar el Control Hub y el Driver Hub para que puedan encender, conectarse entre sí y recibir código correctamente.

Antes de avanzar a programación, el sistema base debe estar estable: Control Hub actualizado, red inalámbrica configurada y Driver Hub emparejado.

<Aside type="note" title="Objetivo de esta fase">
No se busca rendimiento todavía. Primero se busca comunicación confiable entre Control Hub y Driver Hub, y un hardware listo para pruebas.
</Aside>

## Ruta recomendada

<Tabs>

<TabItem label="Robot nuevo">

<Steps>

1. Revisar cableado principal  
2. Confirmar batería cargada  
3. Actualizar firmware del Control Hub  
4. Emparejar Driver Hub  
5. Configurar red inalámbrica  
6. Probar conexión en Driver Station  

</Steps>

</TabItem>

<TabItem label="Robot usado">

<Steps>

1. Revisar firmware desactualizado  
2. Reset de configuraciones previas  
3. Reactualizar o reimagenar Control Hub  
4. Re-emparejar Driver Hub  
5. Validar sensores y configuración de motores  

</Steps>

</TabItem>

<TabItem label="Antes de evento">

<Steps>

1. Verificar batería  
2. Confirmar SSID y contraseña de red  
3. Revisar canal WiFi para evitar interferencia  
4. Test rápido de INIT y START  
5. Driver Hub o teléfono listo con Driver Station  

</Steps>

</TabItem>

</Tabs>

---

## ¿Qué debes validar al terminar?

- El Control Hub enciende correctamente
- El Driver Hub aparece emparejado
- La red inalámbrica es estable y con nombre propio del equipo
- El Driver Station detecta el robot
- El código puede desplegarse
- No hay errores críticos de comunicación

<Aside type="tip" title="Consejo real">
Si el robot no conecta, normalmente el problema está en red, emparejamiento o energía, no en el código.
</Aside>

## Errores comunes

- SSID o contraseña de red incorrecta
- Firmware del Control Hub desactualizado
- Driver Hub sin emparejar
- Batería baja o conector suelto
- App Driver Station desactualizada
- Canal WiFi saturado en el evento
